Invest in a compounding user-and-builder network, not a generic chatbot, exchange clone, or speculative token-only community.

### One-line thesis and customer promise
**SignalForge is the AI-native market operating system: a persistent research-and-action agent that turns fast-moving crypto information into source-linked intelligence, measurable workflows, and user-authorized market actions.**
Public positioning: **"Understand the market. Build your edge. Put your research to work."**
Short tagline: **"Markets move. Your intelligence compounds."**
Always distinguish generated analysis, probabilistic scenarios, backtests, paper results, live reported quotes, executed real orders, and settled proceeds.

### Operating principles
1. Preserve existing premium OHLC terminal, Kraken provenance labels, scanner, models/strategies, backtesting, track record, Token Radar, Polymarket/Hyperliquid read-only pulse, saved research, Signal Rooms, authentication, Stripe Pro/Quant, GitHub/Railway/Postgres, and Sina Founder OS M20 integration.
2. Build three interoperable customer loops: researcher daily utility, agent-builder extensibility, and token/community participation. A user can obtain full useful value without holding a token.
3. Separate independent **internal Company OS** (build/operate SignalForge) from **customer-facing Agent Runtime** (private user jobs and integrations). They may reuse vetted infrastructure but NEVER share execution authority, wallets, private data, budgets, or tenant contexts.
4. Genuine paid subscriptions/API purchases and verified delivered research precede promotional finance claims. Tokens are not substitutes for real revenue.
5. No unconditional trading authority from model text, social posts, third-party Skills, or untrusted market data; automate only within the actual user's bounded, revocable grants and approved integration.
6. Default to fast, bounded implementation. Do not use speculative legal/commercial uncertainty to halt independent research, UI, documentation, community, points, simulation, or subscription features. Perform actual jurisdictional classification before activating real regulated functions.
7. Factual status follows proofs: SOURCE / PLANNED / TESTED / STAGING / PRODUCTION VERIFIED / REAL USER / SETTLED CASH / ONCHAIN RECEIPT. Do not conflate them.

## 3. Critical differentiated loops
**Research loop:** search/source → hypothesis → data capture and counter-thesis → saved state → alert on relevant change → revisit and annotate outcome → share reproducible card → peers return.
**Agent loop:** plain-language intent → clarify only missing trade-critical dimensions → scoped tool selection → observation → simulation or action preview → bounded execution if authorized → verifiable artifact and usage cost → persistent memory.
**Builder loop:** compose widget/skill → pass provenance + safety validation → publish public listing → install/use/clone → charge per usage/subscription (where implemented) → creator payout reconciliation → community visibility.
**Community loop:** meaningful research contribution → peer validation → reputation → qualified invite → return use → membership/API purchase → optional points/token eligibility. No rewards for fabricated clicks, circular trades, sybil wallets, or wash volume.
**Token loop:** real product demand for compute/automation/API/features → optional utility token usage, incentives tied to verified creation → measured treasury and emissions → published onchain supply/vesting; not a price-pump or yield promise.

## 6. Key metrics and anti-vanity definitions
- **WQRR** retained: unique eligible real users completing source-linked useful research on two distinct days within seven days. Currently unmeasured until instrumented.
- **TTFV**: seconds from entry to first trustworthy market answer.
- **WARA**: weekly active real users whose customer Agent completes a source-backed task; bot/test traffic excluded.
- **Thesis return rate**: users reopening a saved thesis after a new observation.
- **Verified research artifacts**: public or private, reproducible, source-linked and successfully generated.
- **Paid conversion / renewal / net MRR / refunds / gross margin / LLM and provider COGS**.
- **Builder activation**: real published usable widget/skill with a non-owner installation.
- **Referral quality**: invited user reaches source-backed activation and later-day return; not raw invitations.
- **Token indicators**, if implemented: distinct eligible users, verified claims, contracted circulating supply, unlocks, treasury wallet accounting, utility consumption; never treat token trade volume as product revenue or active user count.
- **Trade metrics**, if implemented: eligible users, confirmed order acknowledgements, reconciliation, error/duplicate/slippage rates; no simulated PnL presented as realized returns.
