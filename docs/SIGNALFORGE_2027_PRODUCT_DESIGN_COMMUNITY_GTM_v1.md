# SIGNALFORGE 2027 — PREMIUM PRODUCT DESIGN, DAILY USE, COMMUNITY & GTM v1
**Status:** Proposed UX + growth specification, not shipped UI or audience evidence. Baseline: existing Terminal, welcome, radar, web3 pulse, community, billing. Do not replace functionality with a nonworking marketing mockup.

## 1. Brand system and narrative
Category: **AI-Native Crypto Intelligence & Agent Workspace**, not "another trading bot" or "another token launch".
Headline: **"Markets move. Your intelligence compounds."**
One-liner: "Research prediction markets, perp flows and onchain tokens with an AI agent that finds evidence, tests your theses, watches the changes and helps you act deliberately."
For builders: "Build a market tool by describing it. Publish the result. Earn when it delivers verified value."
For community: "Every thesis has a source. Every result has a timestamp."
Narrative ladder: chaotic markets → attention without conviction → evidence and reproducible insight → personal memory and monitor → verified action and review → shared intelligence economy.
No faux trading returns, market data, VIP counts, agents, partner badges or investor endorsements.

## 2. User information architecture
Top-level desktop navigation:
**Explore** (prediction/perps/Solana radar) | **Terminal** (charts, scanners, strategy lab) | **Agent** (conversations, workflows, tasks) | **Studio** (templates, widgets, skills) | **Rooms** (community, research feed, rankings) | **Rewards** (quests, points, referrals, eventual token) | **Account/Wallet** (connections, billing, policy, receipts).
Mobile: bottom tab Explore / Agent / Terminal / Rooms / Profile, with Studio and Rewards reachable via Profile and discovery; use in-app action search and command palette.
The homepage prioritizes usable live-sourced market previews and a free first-use question; token and Company OS are not the hero.
Do not remove /app, /radar, /web3 and existing /app?view= allowed paths; add redirects and navigation links only when active implementations exist.

## 4. Golden flows
**Anonymous first-value <60 sec:** entry specific lane → actual sourced market observation with timestamp → clear "What changed/what is unknown" → ask follow-up or save → optional signup. No email wall before free useful value.
**Researcher daily habit <3 min:** subscribed watchlist opens to changes since last visit → Agent highlights source-backed deltas and contradictory evidence → one-click keep/modify thesis → alerts/revisit.
**Beginner:** select "Explain in plain language"; definitions for OI, funding, implied odds, liquidity; transparent limits; no unearned PnL.
**Power user:** multi-panel terminal, advanced screener, watchlists, strategy simulator, export CSV/JSON, provenance graph.
**Agent builder:** plain language specification → approved tool selection → widget preview and tests → publish with source/cost scope → install/share and track genuine usage.
**Token participant:** discover Quest Board with clear points vs token statuses → connect optional wallet → read disclosures and tracked contributions → when real eligibility exists, view signed claim receipt.
**Trader:** research → paper order → connected venue/account eligibility → user-signed exact order preview → external venue receipt → journal and thesis postmortem. Hide trade CTA where execution unavailable; still offer paper trade.

## 5. Component requirements
- Terminal header: market selector, connected venue badge, last refresh, mode LIVE_PUBLIC_DATA/SOURCE_OBSERVED/DEMO_DATA, search and wallet optional.
- Evidence panel: provider URL, data field timestamp, fetched_at, coverage gaps, hypothesis/counter-thesis, invalidation.
- Agent pane: prompt input, tool activity timeline, estimated/actual cost, sources, task cancel, save/export, follow-up and provenance.
- Monitor cards: trigger, threshold, target market, delivery channels, expiry, last successful check, pause controls.
- Studio: template list, permissions, sample input/output, metered cost, version, test case, publication review and external usage.
- Rooms: quality-first feed, reply citations, report, pseudonym profile, reputation history and moderation status.
- Quest Board: season, eligibility, verified proofs, pending/rejected appeals and available points; no fake onchain balance.
- Referral: ref URL, opt-in privacy, qualified activation status and actual credit ledger.
- Wallet/Trade: connected-account scope, warning of platform support, session revoke, transaction history and provider links.
- Billing: actual current Pro/Quant features, correct provider checkout, upgrade/downgrade/cancel and invoices; never label a selected plan as paid.

## 6. Daily retention product loops
**Morning Pulse (opt-in):** three meaningful cross-venue research changes, fresh sources and user's followed assets; no noise. Deliver via in-app/email initially, Telegram later with consent.
**Market Thesis Timeline:** source snapshot → claim → expiry/invalidation → follow-up outcome and update history; journal distinguishes prediction from hindsight.
**Community Research Challenge:** event/perp/token weekly challenge, equal access to free users, judge by source quality and reproducibility, not speculative PnL or referral count.
**Watchlist Moment:** a specific catalyst changes, user reopens the same artifact; push only when threshold and user relevance qualify.
**Weekly Forge Brief:** sourced public research digest by user/analyst with appropriate rights and consent; each chart/card naturally links to relevant product route.
**Builder Showcase:** functioning externally useful research widget posted with installation count, source and update changelog; merit-based curation.

## 8. Community organization and culture
Five public roles: Explorer → Researcher → Source Reviewer → Builder → Steward. Role progression through reproducible useful work, never purchase volume. Separate internal moderators and internal Company OS operators from community badges.
Rooms: Prediction, Perps, Solana Trenches, Strategy Lab, Agent Builders, Verified Research. Each features pinned methodology, active high-quality thesis, counterarguments, searchable history, source guidelines and moderation.
Moderation: warnings, throttling, spam/sybil signals, conflict-of-interest and sponsored-research disclosure, impersonation handling, appeal logs; only real members in metrics.
Optional research bounties funded by actual budget, accepted deliverables and payment receipts; do not imply token compensation until live.
Public launch scoreboard: SOURCE-CHECKED posts, real contributors, sample-linked work and verifiable receipts only.

## 9. Referral design, not another vanity funnel
Referral rewards after qualified first research and a separate-day return or paid entitlement, not raw signups; avoid fake incentives. Give both sides limited research/monitor credits, with bounded per-referrer/month limit. Transparent attribution rules, first-party cookie consent and fraud appeals. Optional future token program is separate from immediate credits.
Suggested test matrix:
A: invite researcher to a specific Event/Perps/Token research card.
B: invite collaborator to review a shared thesis.
C: invite builder to clone a public widget (when implemented).
Measure verified activation, D7 WQRR, paid conversion, abuse rate and contribution margin, not link clicks alone.

## 10. Pricing and free/paid surfaces
**FREE:** public market observations, limited sourced Agent runs, sample backtests/one saved thesis, public Rooms and quests, optional alerts quota. Pricing/quotas must reflect actual implementation.
**PRO:** increased monitor/watchlist/Agent budget, export, private journals and recurring research briefs. Use existing configured Stripe entitlement rather than invented amounts.
**QUANT:** expanded strategy jobs, advanced backtest, reproducible datasets, team/research workspace where shipped; price based on real COGS and demand.
**DEVELOPER/API:** metered source-linked research endpoint/agency API when working; x402 optional after cash proof.
**BUILDER MARKETPLACE:** creator revenue shares only for verified paid customer usage, settlement after refunds/fraud windows.
Token holders cannot bypass necessary fiat billing or consume unlimited external inference cost by holding an unpriced asset.

## 11. Marketing production system
Weekly rhythm: Mon public sourced event brief; Tue perp-market observation; Wed Solana mint teardown; Thu builder demo; Fri "what our past theses got wrong" post; weekend community research challenge. Every artifact tagged with venue, timestamp and links. AI may draft; claims and posts must be source-checked, have permission to publish and actual provider posting receipts before counted.
Channels: X/Farcaster public threads, trusted Telegram/Discord rooms, GitHub demo repos and discussions, relevant Reddit communities (respect rules), SEO landing pages for real venue queries, opt-in email digests, partner directory inclusion after acceptance.
Community manager asks quality questions, responds to actual market source issues, invites a small meaningful cohort; no anonymous fake social accounts.

## 12. Product and brand differentiation from Bankr
Learn Bankr's persistent agent and distribution loop. Do NOT replicate its interface, licensed code, trademarks or assume unrestricted partner API use. SignalForge focuses on cross-venue evidence, calibratable research, long-lived hypotheses, strategy validation and research-to-action; wallet and launchpad are optional financial layers rather than the only reason to participate.
User can use the platform every day even with no trade, token or paid subscription.

## 13. Accessibility, localization, identity
English baseline; externalize strings for future Arabic, Persian, Spanish, Portuguese, Turkish, Hindi, Indonesian, Vietnamese, French, Chinese and Japanese based on real adoption. Use proper RTL layout and locale-aware number/currency/date presentation, not literal machine translation of financial terms without review. 24-hour time and source timestamps with user timezone. Seed phrases, wallet IDs and personal details must never be published in shared research cards.

Screen-by-screen functional paths for desktop/mobile; read-only anonymous flow; auth and retention; actual source timestamps; source outage fallback; no placeholder CTA; keyboard accessibility; alert unsubscribe; real moderation; signed Stripe payment; truthful tool costs and token statuses.
